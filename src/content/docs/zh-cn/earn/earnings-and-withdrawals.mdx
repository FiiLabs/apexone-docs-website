共享者的收益进的是一个与消费余额分开的钱包。钱会经过三种状态，在你去找一个「好像不见了」的数字之前，值得先搞清楚它们的区别。

## 钱经过的三种状态

| 状态 | 含义 | 能提现吗 |
| --- | --- | --- |
| **冻结中** | 已入账，仍在 72 小时冻结窗口内 | 否 |
| **待提现** | 冻结期已过 | 是 |
| **累计收益** | 只增不减的累计值 | ——（这是流水总计，不是余额） |

<Aside type="tip" title="两个余额，两套规则">
	如果你同时也在**使用** ApexOne，那你现在有两笔钱，而它们的命名是刻意分开的。
	**账户余额**是你充值进来的——只能花掉。**待提现收益**是你赚到的——可以提到自己的链上地址。
	它们不会按你可能以为的方向互通：充值不会变成收益。
</Aside>

## 为什么要有冻结期

消费者可以用银行卡付款，而卡付款事后是可以被拒付的。如果一笔请求计费的当下就把钱打给共享者，一旦发生拒付，平台就要自己贴上那笔已经发出去的钱。

冻结期是 **72 小时**。这是一次刻意的取舍，而不是「越安全越好」：

- 三天覆盖的是真正会很快浮出水面的欺诈——一张被盗的卡通常在几天内就会被发现并发起争议，而绝大部分争议金额就落在这段时间里。
- 更长的冻结期能覆盖长尾，代价是让每一个共享者为已经赚到的钱多等几周。对付长尾该用的工具是部分准备金，而不是把所有钱都扣住。

<Aside type="note" title="这个数字在哪里设置">
	冻结时长是站点配置项，不同部署可以取不同的值。你的账号实际适用的时长，会显示在控制台余额旁边。
</Aside>

## 怎么拿到钱

<Steps>

1. **绑定收款地址。**

   打开共享控制台，滚动到提现区域。从你的钱包里**复制**地址粘贴进来——不要手打，也不要凭记忆「改正」某一位字符。点击**绑定**。

   这一步只需要做一次。之后重新绑定不会影响已经提交的申请：每一笔申请都记录了它创建那一刻所绑定的地址。

2. **确认金额确实可提。**

   表单显示的是此刻可用的金额。仍在冻结窗口内的部分不计入其中——如果这个数比你预期的低，通常就是这个原因，而不是出错了。

3. **提交申请。**

   填写金额（或者用「全部可用」的快捷方式）后提交。**金额在你提交的那一刻就离开待提现余额**，而不是在打款时才扣——表单上写明了这一点，但仍然有人会被它绊到。如果申请之后被驳回，或者你自己取消，全额会退回来。

4. **等待到账。**

   申请会经过 `pending` → `processing` → `paid`。打款完成后，记录里会带上链上交易哈希——你可以把它粘进区块浏览器，自己确认这笔转账。

   提现**零手续费**：网络 gas 由平台承担，所以你申请多少就到账多少。

</Steps>

<Aside type="note" title="中间那两个状态是什么意思">
	`processing` 表示转账正在广播——这是唯一不提供取消的状态，因为取消可能与一笔在途转账抢跑。
	`failed` **不代表钱没了**：它表示自动打款没有完成、正由人工接手处理，金额仍然挂在这笔申请上。
</Aside>

<Aside type="danger" title="链上转账不可逆">
	如果绑定的地址是错的，转账照样会成功——转给那个地址的主人。没有任何下游手段能追回，平台也无法撤销。
	请从钱包里复制地址，并在绑定前再核对一遍。
</Aside>

## 容易让人意外的几件事

**「我一点提交，余额就少了。」** 这是设计如此，表单上也写了。改成审批时才扣的话，会留下一个窗口，让同一笔余额被提交多次提现。

**「累计收益和待提现对不上。」** 差额是仍在冻结窗口内的那部分，加上已经提走的部分。累计收益只增不减，它是一个终身计数器，不是余额。

**「账号接上了但没有收益。」** 先看它的状态。处在观察期的账号还没有开始接单。而一个已经在接单却没有收益的账号，说明没有需求被路由过来——那是平台侧的现实，不是你这边配置错了。

**「我用自己的 Key，结果没有收益。」** 你用自己的 API Key 发出的请求，如果恰好落在你自己共享的账号上，是不计分成的。给自己付的钱再分自己一笔，等于凭空造钱，所以这条路径被刻意排除了。
