**ApexOne 是可验证的前沿 AI 网关。** 它让开发者、Agent 与企业通过一个统一的、**OpenAI 兼容**的 API 调用全球最先进的大语言模型——并且提供了一条别的网关不会给你的保证：**你可以验证每一次请求确实由你付费的那个模型完成。**

普通的 API 聚合平台要你信任它。ApexOne 把「信任」这一环去掉了——路由决策、模型身份与计费，全部可以独立验证。

<Aside type="tip" title="AI 调用的信任层">
	可以把 ApexOne 理解成 AI 调用的 HTTPS。干活的是前沿模型；ApexOne 证明的是**究竟哪个模型**干的——
	因为「用一个模型」和「信任这个模型」本来就不该是两件事。
</Aside>

## ApexOne 有什么不同

<CardGrid>

### 「可验证的推理」具体指什么

- **模型身份保证**——每一次响应都带有可验证的记录：哪个模型、哪个版本、哪个提供方真正服务了它。
- **推理回执**——每一次请求产生一张可审计的回执（模型、路由、时延、token 数），可留存用于合规、排障与对账。
- **透明路由**——自动故障切换改道一次请求时，这次改道是可见且被记录的，绝不隐藏。你始终知道跑了什么、为什么。

不必只听我们说——看看怎么[**自己验证**](/zh-cn/verification/privacy-proof/)：真实的硬件、未被篡改的代码，当场证明。

## 你的请求是怎么被服务的

供给通过三条路由到达 ApexOne。它们的区别在于**你的 prompt 走到了哪里**，所以我们把每一条分别讲清楚，而不是笼统地下一个结论。

| 路由 | prompt 去了哪里 | 在 TEE 封装内吗 |
| --- | --- | --- |
| **平台自营账号** | 在 Intel TDX 机密虚拟机内路由——运营方与日志都读不到明文 | **是** |
| **共享订阅** | 共享者只贡献闲置的订阅额度。请求从 TEE 直达上游厂商，不经过共享者的任何设备 | **是** |
| **共享者 API 中转** | 转发到共享者自己提供并运维的端点 | **否** |

<Aside type="caution" title="中转路由对你意味着什么">
	在中转路由上，你的请求内容到达的是第三方共享者运维的服务器，而不是直达模型厂商。
	这是「中转型供给」这件事本身的属性，不是网关能在工程上抹掉的——所以我们把它讲出来，
	而不是把它平均进一句「我们读不到你的数据」。站点运营方可以把中转路由整个关掉。
</Aside>

<Aside type="tip" title="用了别人的订阅，不等于对方能读到你的 prompt">
	共享订阅这条路由是最常被误读的。共享者贡献的是**额度**，不是服务器：请求离开我们的 TEE 后直达上游厂商。
	共享者看不到任何内容——他们只能看到自己的额度被消耗了。
</Aside>

## 支持的能力

- **流式输出**，实时响应
- **工具与函数调用**，支撑 Agent 工作流
- **结构化输出**，可靠地解析数据
- **视觉与长上下文**模型
- **高吞吐**，面向全球规模构建
- 每一次请求都带**可验证的路由与推理回执**
