## 我们的承诺（以及诚实的边界）

<Aside type="tip" title="我们保证什么">
	在你的设备与上游模型厂商之间，**没有任何中间环节能读到你的 prompt**——包括作为运营方的我们。而且你不必凭信任接受这句话：机密计算机内运行的代码是公开的，它的指纹由 Intel 硬件签名。
</Aside>

<Aside type="caution" title="我们不夸大什么">

- **上游模型厂商能看到你的明文。** 一个被路由到 Claude、GPT 或任何托管模型的请求，最终必须以明文到达那家厂商，并在**它的**隐私政策下被处理。我们从不宣称对模型厂商保密。
- **我们不宣称「你的模型没有被替换」。** 这一点请以你实际收到的回复、以及下面列出的证据来判断。
- **我们不宣称我们什么都不记录。** ApexOne 是一个网关：它保有任何网关都需要的用量与计费数据。硬件证明确立的是**哪份代码**在运行——而不是对那份代码选择存什么做出承诺。代码是公开的，去读它。
- **有些原始固件寄存器没有公开的参考值。** `/proof` 页面会把它们显示出来，并**明确标注为未验证**，而不是伪造一次比对。操作系统镜像的身份改由另一项完整校验过的度量来锚定。

</Aside>

我们把边界划得这么清楚，是为了让我们**能够**证明的那部分真正值得信任。

## 怎么自己验证

<p><Badge text="约 30 秒" variant="success" size="medium" /></p>

<Steps>

1. 打开 [**apex1.us/proof**](https://apex1.us/proof)。

2. 页面会**自动**在你的浏览器里开始验证——你会看到各项检查从「检查中…」变成绿色的「已验证」。

3. 全绿意味着：**真实的 Intel 机密硬件 + 运行的正是那份公开、未被篡改的代码 + 证明是此刻生成的**（而不是旧的、被重放的）。

</Steps>

整个过程**在你自己的浏览器里完成，不依赖我们的服务器**——它向芯片厂商 **Intel 的信任根**求证「这是真实硬件，跑的是那份公开代码」。你随时可以点**重新验证**；页面会取一个新的一次性随机数再校验一遍。

### 每一项检查证明了什么

| 你会看到的条目 | 平实的含义 |
| --- | --- |
| 证明数据完整性 | 硬件报告完整抵达，格式正确。 |
| 真实的 Intel 机密硬件 | 不是一台普通服务器在冒充——是真芯片，对着 Intel 自己的证书链与吊销数据验证过。 |
| 一次性随机数绑定 | 这份证明是**此刻**为你生成的：你浏览器刚造的那个随机数被烘进了硬件报告里。 |
| 度量日志真实性 | 启动与加载过程的记录被重放，并被证明与硬件寄存器一致——日志无法在事后被修改。 |
| 应用身份 | 这个部署就是我们公布的那个，不是一个长得像的。 |
| 部署指纹 | 它运行的正是我们公布的那份部署，一个字节都没改——而且**独立核对了两遍**：一遍来自度量日志，一遍直接读硬件寄存器。 |
| 操作系统镜像指纹 | 底下的操作系统是公布过的、未经修改的镜像。 |
| 加密密钥绑定 | 你要加密给它的那个公钥本身也被硬件证明覆盖——所以「只有飞地能解密」这件事由 Intel 硬件背书，而不是靠我们一句话。 |
| 原始固件寄存器 | 完整列出，并标注为**仅供参考**：它们没有公开的参考值，所以不做任何比对。我们宁可把这个缺口摆出来，也不伪造一次匹配。 |

## 进阶：实时端到端加密实测

在 `/proof` 页面底部有一个**可选**的实时测试，让你**亲眼看到**中间环节读不到你的 prompt。与自动验证不同，它会发起一次**真实的推理请求**——所以需要 API Key、一个模型，以及一点点额度。按下**加密并往返一次**，你的浏览器会：

<Steps>

1. 在**本地**把你的 prompt 加密成只有那台机密计算机的硬件证明密钥才能打开的密文。

2. 把密文发到真实的推理端点，再把返回的加密模型响应解密。

3. 把每一方分别看到了什么原样展示给你：

</Steps>

<CardGrid>
	<Card title="你，在自己的浏览器里">
		👁 **明文**——你的 prompt 与解密后的回复。
	</Card>
	<Card title="中间环节（ApexOne 的网络路径、任何中间设备）">
		🚫 只有一团**密文**，无法还原。
	</Card>
	<Card title="那台机密计算机">
		🔓 能解密——而且**只有**它能，这正是你收到真实回复的原因。
	</Card>
</CardGrid>

回复能被解密并通过完整性校验，**就证明了**只有持有受硬件保护私钥的那台机密计算机才能打开你发出的内容。这个结论**无论你是否信任网络层加密都成立**——而且你可以自己确认：打开浏览器开发者工具的 Network 面板，看那个请求体，里面除了密文什么都没有。

<Aside type="caution" title="试之前请注意">
	这个演示 prompt 会在机密计算机内被解密，然后按设计以明文转发给上游模型厂商（第 3 步），并且会消耗少量额度。**不要粘贴任何敏感内容。** 你的 API Key 留在浏览器里，只用于授权那一次请求。
</Aside>

## 独立核对

不想只听我们说？你不必。[**apex1.us/proof**](https://apex1.us/proof) 页面公布了当前部署确切的参考值（那些「指纹」），并让你——或者任何独立第三方——逐行与实时读取的硬件证明比对。**如果数值吻合，正在运行的代码就真的是我们所宣称的那份公开、未被篡改的代码。**

你需要的一切都在 `/proof` 页面上：

- **当前的参考值**——App ID、部署指纹、操作系统镜像、源码 commit，以及确切的容器镜像摘要；
- 指向公开源码（[FiiLabs/sub2api](https://github.com/FiiLabs/sub2api)）、被度量的部署文件，以及产出 **cosign 签名镜像与 SLSA provenance** 的公开构建流水线的**直达链接**；
- 一键**下载证明报告**，你可以拿到独立的浏览器里重新核对，例如 [proof.t16z.com](https://proof.t16z.com/)；
- 验证依据的是 **Intel 自己的证明数据**，不是我们的。

参考值不是写死在页面里的——它们是从公开仓库里的一个文件实时拉取的，所以**对它们的每一次改动都是公开的 git 历史**。这是刻意的：意味着我们无法在事后悄悄挪动球门。

<Aside type="note">
	我们刻意把具体的指纹数值放在 `/proof` 页面上而不是这份指南里：这里描述的**验证方法**不会变，而具体指纹在我们每次发版时**都会**变——页面上永远是当前的那一份。于是这份指南长期有效，页面长期实时。
</Aside>

## 常见疑问

### 验证会用到我的数据、API Key 或额度吗？

取决于你指的是页面上哪一样：

- **自动验证**（页面打开时自行运行）是**只读且免费的**。它只用公开数据核对硬件证明——不发送你的任何内容、不使用 API Key，也不会动你的余额。
- **可选的实时加密实测**（只有你按下**「加密并往返一次」**才会运行）会发起一次真实的 API 调用，用来证明中间环节读不到你的 prompt。和任何真实请求一样，它会用到你的 API Key 和极少量额度（不到一分钱）——所以如果你验证完之后余额少了一两分，**那是这个实测，不是自动检查。** 你的 API Key 留在浏览器里，只用于授权那一次请求；我们不会存储它。

### 如果验证显示「无法完成」或「失败」怎么办？

先按**重新验证**再试一次——偶发的网络问题（比如 Intel 的验证数据服务暂时不可达）会产生「无法完成」，那既不是通过也不是失败。如果它持续报告**明确的失败**，请**不要信任**那个部署，并[联系我们](mailto:support@apex1.us)。

### 这能保证模型厂商看不到我的内容吗？

**不能**，我们也从不这样宣称。任何托管模型都必须拿到明文才能回答你。我们保证的是：你的设备与那家厂商之间的每一个中间环节，拿到的都只是密文。

### 不懂密码学也能验证吗？

能。打开 `/proof`，看绿色对勾就行。那些术语和参考值是给想深入挖的进阶用户准备的。

<Aside type="note">
	本文描述的是 ApexOne 生产环境（`apex1.us` 与 `api.apex1.us`），它作为单一的 Intel TDX 机密虚拟机运行。参考值在每次版本更新时刷新；实时验证永远反映 `/proof` 页面当场读到的内容。
</Aside>
