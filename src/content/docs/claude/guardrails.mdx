## System-level permission rules

The pre-installed Claude Code ships with system-level settings (`/etc/claude-code/managed-settings.json`, owned by root). They take top priority and Claude cannot change them. By default Claude:

- doesn't read common secret paths such as `~/.ssh`, `~/.aws`, `~/.kube`, `.env` and `*.pem`;
- doesn't run `sudo`, `su`, firewall changes, `nsenter` and similar commands.

<Aside type="caution" title="An honest boundary">
	Permission rules are a **convenience guardrail, not a security boundary**: Claude could still read those files with a differently written Bash command. What actually carries the weight is `~/private` below.
</Aside>

## ~/private: completely invisible to Claude

Claude Code runs in an isolated namespace where `~/private` is an empty, read-only directory — no command can read through it. Keep anything you don't want Claude to touch (private keys, cloud credentials, production config) there.

```bash
hangar private     # what it protects against, and what it doesn't
```

## Check or turn off

```bash
hangar security          # current hardening status
sudo hangar security off # turn hardening off (needs sudo — Claude has none)
sudo hangar security on  # turn it back on
```
